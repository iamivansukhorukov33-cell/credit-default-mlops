# Сценарий защиты (5–7 минут)

1. Объяснить задачу: вероятность дефолта следующего месяца, источник UCI, 23 признака.
2. Показать структуру src/tests и историю `git log --oneline`.
3. Открыть EDA: дисбаланс, распределения, обработка EDUCATION/MARRIAGE; ID исключен.
4. Показать `pytest -q`: аномалии возраста, null и неверные классы останавливают GX.
5. Объяснить Pipeline: признаки → imputer → scaler / one-hot → классификатор. Все обучаемые преобразования внутри CV.
6. Показать пять запусков в MLflow и выбор по CV ROC-AUC, затем test-метрики и ROC.
7. Выполнить `dvc repro`: неизмененные стадии пропускаются. Показать `dvc.lock`.
8. Запустить API, отправить `python -m scripts.api_smoke`; показать Swagger и ошибку 422 при неполном запросе.
9. При работающем Docker собрать образ и повторить API smoke test из контейнера.
10. Запустить `python -m src.monitor`, объяснить PSI и ограничения имитации.
11. После публикации показать зеленый GitHub Actions. Отдельно назвать непроверенные пункты из verification.md.

Термины: train — обучающая выборка; test — отложенная выборка; cross-validation — кросс-валидация; artifact — сохраненный результат; reproducibility — воспроизводимость; drift — изменение распределения данных.

## Короткий рассказ для защиты

«Я разработал пайплайн, который оценивает риск дефолта по кредитной карте в следующем месяце. На вход подаём кредитный лимит, суммы счетов и историю платежей. Перед обучением проверяем данные. Например, автоматический тест подставляет возраст 150 лет и проверяет, что валидация его отклоняет.

В MLflow сравнил пять запусков. По кросс-валидации выиграл градиентный бустинг. На отложенных данных получили ROC-AUC 0,7797. При пороге 0,5 модель находит около 35% дефолтов, поэтому порог для практического применения нужно выбирать с учётом цены ошибок.

DVC связывает подготовку данных и обучение. Сейчас покажу, как FastAPI принимает данные клиента и возвращает прогноз. Для мониторинга отправили 300 запросов и сравнили распределения с обучающими данными. В этой партии порог PSI не сработал».

Для быстрой демонстрации откройте ROC-кривую и таблицу запусков заранее. Вживую достаточно показать тесты и один ответ API. Вывод DVC, состояние CI и запуск Docker покажите, если проверили их перед защитой.
